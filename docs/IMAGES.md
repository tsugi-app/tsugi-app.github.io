# 츠기 대표 이미지 가이드라인

> 장소(place)마다 한 장씩 두는 대표 이미지를 **Claude(Opus)가 직접 그린 SVG 일러스트**로 만든다.
> 사진을 쓰지 않는다. 화면 규칙은 `docs/DESIGN.md`의 Image Frame, 콘텐츠 규칙은 `CLAUDE.md`를 함께 따른다.

---

## 0. 이 이미지가 하는 일

대표 이미지는 **목록에서 장소를 알아보는 표식**이다. 장소를 "보여 주는" 사진이 아니다.

| 해야 하는 것 | 하지 않는 것 |
|---|---|
| 88px 썸네일에서 한눈에 "아, 그 레코드 가게" 하고 떠올리게 한다 | 실제 외관·내부를 사진처럼 재현한다 |
| 출처에 있는 그 장소의 성격 하나를 상징으로 그린다 | 출처에 없는 메뉴·상품·풍경을 지어낸다 |
| 목록 전체가 한 시리즈처럼 보이게 한다 | 장마다 화풍을 바꾼다 |

**정직 원칙 (DESIGN.md "믿어도 되나?")**: 일러스트는 일러스트로 보여야 한다. 사용자가 "실제로 이렇게 생긴 곳"이라고 오해할 만큼 사실적으로 그리지 않는다.

**이미지는 장소에 붙는다, 소식에 붙지 않는다.** 소식(update)은 끝나고 유형도 `limited → editorial`처럼 바뀌지만 이미지는 남는다. 그래서 기간 한정 행사 내용이 아니라 **장소가 오래 가진 성격**을 그린다. (예: seeen은 이번 카슨 전시가 아니라 "안도 다다오 건물 속 갤러리")

---

## 1. 화풍 — "아이(藍) 판화"

한 문장으로: **남색 잉크로 찍은 2~3도 목판화 같은 평면 일러스트.**

- **면으로 그린다.** 단색 면 + 굵은 실루엣. 선은 보조로만.
- **그라데이션·그림자·블러·광택 없음.** 깊이는 면을 겹쳐서만 낸다.
- **시점은 셋 중 하나**: 정면, 옆면, 바로 위. 비스듬한 원근·3D 투시 금지.
- **모티프는 하나.** 주인공 사물 1개 + 받쳐 주는 요소 0~2개. 장면(여러 사물이 있는 풍경)을 그리지 않는다.
- **글자 없음.** 한·일·영 글자, 숫자, 로고, 간판 모두 넣지 않는다. 이름은 화면이 이미 보여 준다.
- 모서리는 살짝 둥글게(`stroke-linejoin="round"`, 작은 반경). 너무 귀엽거나 아이콘처럼 매끈하지 않게, 손으로 깎은 듯 약간 비뚤어도 좋다.

### 1.1 색 — 이미지 전용 팔레트

`<img>` 안의 SVG에는 CSS 변수가 닿지 않으므로 이미지 파일에는 아래 **고정 값만** 쓴다. (컴포넌트에 색 코드를 쓰지 말라는 규칙의 예외는 `content/images/*.svg`뿐이다.)

**바탕 — 동네마다 하나 (화면 전체를 칠한다, 투명 금지)**

| 동네 | 바탕 | 느낌 |
|---|---|---|
| 시부야 | `#e3e6ec` | 콘크리트 회청 |
| 하라주쿠 | `#e2e9de` | 숲 그늘 세이지 |
| 오모테산도 | `#ece5da` | 느티나무 길 돌색 |

**잉크 — 모든 이미지 공통**

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| 아이 진 | `#233c74` | 주 실루엣, 가장 넓은 잉크 면 |
| 아이 | `#5873b5` | 두 번째 면, 겹침 |
| 아이 옅 | `#c3d1ec` | 세 번째 면, 바탕과 잉크 사이 |
| 종이 | `#faf8f4` | 하이라이트·빈 면 (화면의 15% 이하) |
| 겨자 | `#c99a2e` | 포인트 1곳만 (화면의 10% 이하) |

- 한 장에 바탕 1 + 잉크 최대 4색.
- 겨자는 장식이지 의미가 아니다. 소식 유형 색(초록·주홍·노랑)은 배지 몫이므로 이미지에 쓰지 않는다.
- **흑백에서도 읽혀야 한다.** 종료된 소식은 `.thumb.ended`가 `grayscale(1)`을 씌운다. 주 실루엣(아이 진)과 바탕의 밝기 차이로 모양이 보이게 한다.
- **다크 모드**: 이미지는 바꾸지 않는다. 바탕이 불투명한 중간 밝기라 어두운 화면에서도 튀지 않는다. 흰색에 가까운 면을 넓게 쓰지 않는 이유가 이것이다.

### 1.2 모티프 고르기

1. 먼저 **출처가 있는 문장**에서 고른다: take의 `why`·`differsFrom`, update의 `note`, 장소 공식 페이지.
2. 그 장소만의 것이 있으면 그것 (예: 네즈 미술관 → 대나무 벽 진입로를 추상화한 세로 줄).
3. 없으면 카테고리 기본 어휘에서 고른다.

| category | 기본 어휘 (하나만) |
|---|---|
| `cafe` | 컵, 드리퍼, 원두 한 알, 김 한 줄기 |
| `gallery` | 빈 액자, 받침대, 벽에 떨어진 빛 사각형 |
| `design` | 기하 도형 조합, 자, 종이 접힘 |
| `goods` | 그 가게가 실제로 다루는 물건 하나의 실루엣 |
| `mall` | 계단·경사로·처마 같은 건물 요소 하나 |
| `walk` | 길 한 줄기, 나뭇잎, 물길 |

- 고른 모티프가 출처에 없는 사실을 말하게 되면 버린다. (판매 여부를 모르는 상품, 확인 안 된 메뉴 등)
- `checks/*.json`의 `uncertain`에 걸린 내용은 모티프로 쓰지 않는다.

### 1.3 그리지 않는 것

- 로고·상표·간판·브랜드 고유 패키지 (DJI, 맥캘란, 젤라토 피케 등 모두)
- 실존 작가의 작품이나 그 화풍 흉내 (우키요에 특정 작품, 카슨의 타이포그래피 등). 미술관이면 "액자·벽·빛"으로 대신한다.
- 사람의 얼굴·실존 인물. 사람이 꼭 필요하면 얼굴 없는 작은 실루엣까지만.
- 장소와 상관없는 일본 상징: 후지산, 벚꽃, 도리이, 다루마, 욱일 형태 방사선 등
- 건물 외관의 사실적 재현. 건축 요소를 쓸 땐 한 부분을 단순 도형으로 줄인다.

## 2. 캔버스와 안전 영역

이미지 한 장이 세 곳에 잘려 들어간다: 목록 정사각(88·64·48px), 상세 4:3, 공유 미리보기(약 1.91:1).

```
 0                                      1200
 ┌─────────────────────────────────────────┐ 0
 │        ┌───────────────────────┐        │
 │  ┌─────┼───────────────────────┼─────┐  │ 136
 │  │     │                       │     │  │
 │  │     │      핵심 영역         │     │  │   ← 주 모티프는 여기 안에
 │  │     │   x 150–1050          │     │  │
 │  │     │   y 136–764           │     │  │
 │  └─────┼───────────────────────┼─────┘  │ 764   ← 공유 미리보기 띠 (y 136–764)
 │        └───────────────────────┘        │
 └─────────────────────────────────────────┘ 900
          ↑ 목록 정사각 (x 150–1050)
```

- 캔버스 **1200 × 900 (4:3)**. 상세 화면 그대로의 비율.
- 주 모티프는 **핵심 영역(x 150–1050, y 136–764)** 안에, 그 면적의 50~70%를 차지하게 둔다.
- 핵심 영역 밖은 바탕 또는 바탕에 가까운 보조 면만. 잘려도 아무것도 잃지 않아야 한다.
- **48px에서도 읽힌다**: 88px 썸네일에서 캔버스 1단위 ≈ 0.1px이다.
  - 뜻이 있는 형태는 최소 60단위(88px에서 약 6px).
  - 선 두께 최소 18단위. 이보다 가는 디테일은 넣지 않는다.

## 3. SVG 파일 규칙

파일: `content/images/<placeId>.svg` (장소 1개 = 이미지 1개)

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1200 900" width="1200" height="900">
  <title>omotesando-seeen</title>
  <desc>
    모티프: 노출 콘크리트 벽 앞의 빈 액자와 위에서 떨어지는 빛 사각형
    근거: take.differsFrom "안도 다다오가 설계한 건물", place.category gallery
    피한 것: 카슨 작품·맥캘란 병(기간 한정 행사, 상표)
    제작: Claude Opus 5.5 · 2026-11-09
  </desc>
  <rect width="1200" height="900" fill="#ece5da"/>
  …
</svg>
```

- `width`·`height`를 반드시 적는다. 없으면 `<img>`가 비율을 몰라 `object-fit: cover`가 어긋난다.
- 첫 요소는 바탕 `<rect>` (투명 바탕 금지).
- `<desc>`에 **모티프·근거·피한 것·제작 모델·날짜**를 적는다. 다음 사람이 왜 이 그림인지 출처까지 따라갈 수 있게.
- 쓸 수 있는 요소: `g` `path` `rect` `circle` `ellipse` `line` `polyline` `polygon` `defs` `clipPath` `use`
- 쓰지 않는 것: `<text>` `<image>` `<script>` `<foreignObject>` `<style>` `filter` `linearGradient`·`radialGradient` `mask`, 외부 `href`, 폰트
- 색은 `fill`·`stroke` 속성에 1.1 팔레트 값만.
- 좌표는 정수(필요하면 소수 1자리). 파일 크기 **30KB 이하**, 경로 약 80개 이하.

### 3.1 place JSON

```json
"image": {
  "file": "omotesando-seeen.svg",
  "credit": "츠기 일러스트 (Claude Opus 제작)",
  "license": "츠기 자체 제작"
}
```

`credit`·`license`가 없으면 `validate.mjs`가 막는다. 사람이 다시 그리거나 고치면 `credit`에 이름을 더한다.

## 4. 만드는 순서 (Claude)

1. **읽기** — 그 장소의 place·take·update·check를 모두 읽는다. `uncertain`을 따로 적어 둔다.
2. **브리프 3줄** — 모티프 / 근거(필드와 문장) / 피한 것. 이게 그대로 `<desc>`가 된다.
3. **그리기** — 1장의 화풍·팔레트, 2장의 안전 영역 안에서.
4. **미리 보기** — 앱에서 실제 크기로 본다: 목록 88·64·48px, 상세 4:3, 흑백(`.ended`), 다크 모드.
5. **나란히 보기** — 이미 있는 이미지들과 한 화면에 늘어놓고 시리즈로 어울리는지 본다. 혼자 튀면 고친다.
6. **자기 검토** — 아래 체크리스트를 모두 통과하면 place JSON에 `image`를 넣고 `npm run validate` → PR.

### 4.1 체크리스트 (병합 전)

- [ ] 모티프가 출처 있는 문장에 기대고, `<desc>`에 근거가 적혀 있다
- [ ] 기간 한정 행사가 아니라 장소의 오래가는 성격을 그렸다
- [ ] 글자·로고·상표·실존 작품·얼굴이 없다
- [ ] 바탕은 그 동네 색, 잉크는 팔레트 값만, 4색 이하
- [ ] 주 모티프가 핵심 영역 안에 있고, 48px에서도 무엇인지 알아본다
- [ ] 흑백으로 바꿔도 모양이 보인다
- [ ] 다크 모드 화면에서 혼자 밝게 튀지 않는다
- [ ] 금지 요소가 없고 30KB 이하다
- [ ] 다른 이미지들과 나란히 놓아도 한 시리즈로 보인다

**처음 세 장은 사용자가 보고 화풍을 정한 뒤 병합한다.** 그 뒤로는 카드와 같이 체크리스트를 통과하면 Claude가 병합한다.

## 5. 기계 검사와 남은 일

- **공유 미리보기**: 카카오톡·X·페이스북은 `og:image`로 SVG를 보여 주지 않는다. `scripts/build-share.mjs`는 이미지가 `.svg`면 기본 `og.png`를 쓴다. 장소별 OG 이미지가 필요해지면 PNG 변환 방법을 정한다 (라이브러리 추가 없이: macOS `qlmanage`/`sips`, 또는 CI의 헤드리스 Chrome).
- **`validate.mjs`가 막는 것**: 3장의 금지 요소, `viewBox`·`width`·`height`, 30KB 초과, 1.1 팔레트 밖 색, `<desc>`에 근거가 없는 파일. 팔레트를 바꾸면 `validate.mjs`의 `SVG_PALETTE`도 같이 고친다.
- **앱인토스**: WebView의 `<img>` SVG 표시를 실기기에서 한 번 확인한다.
