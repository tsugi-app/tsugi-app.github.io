# 츠기 UI/UX 가이드라인

> 기반: 당근 디자인 시스템 **SEED** (seed-design.io, `@seed-design/css` 3.2.0 토큰 값 참고)
> 원칙: SEED의 **구조**(시맨틱 토큰·스케일·컴포넌트 규격·문구 규칙)를 따르고, **정체성**(브랜드색·노선 메타포·편집 목소리)은 츠기 것으로 둔다.
> 라이브러리는 추가하지 않는다. SEED 값을 `app/src/styles/tokens.css`에 옮겨 적어 쓴다.

---

## 0. 츠기가 해결하는 한 가지

사용자는 이미 일본 여행 일정을 짜 두었다. 츠기는 **"그 일정에 끼울 한 곳"을 10초 안에 고르게** 돕는다.
모든 화면 결정은 아래 세 질문으로 판단한다.

| 질문 | 화면에서의 뜻 |
|---|---|
| **언제 갈 수 있나?** | 기간·D-day·예정 여부가 이름 다음으로 크게 보인다. |
| **왜 가나?** | 편집 판단(`why`) 한 줄이 목록에서도 보인다. |
| **믿어도 되나?** | 상세의 확인일·불확실 항목과 목록의 "재확인 필요" 배지가 숨지 않는다. |

### 경험 원칙 (SEED Voice & Tone의 "명확한·이해하기 쉬운·사려 깊은"을 츠기에 맞춤)
1. **고르기 쉽게** — 목록은 훑기용, 상세는 결정용. 목록 한 줄에 판단 재료(유형·기간·동네·이유)를 다 담는다.
2. **기간이 먼저** — 끝나 가는 소식은 색과 D-day로 먼저 알린다. 끝난 것은 자동으로 빠진다.
3. **정직하게** — 모르는 값은 비우고 "확인 중"이라고 쓴다. 꾸며 채우지 않는다.
4. **여행 중 한 손으로** — 누를 곳은 최소 44px, 주요 행동은 화면 아래 엄지 영역에 둔다.
5. **기기 밖으로 쉽게** — 지도·공유·보관 링크는 언제나 한 번에 닿는다.

## 1. 파운데이션

### 1.1 색 — 시맨틱 토큰만 쓴다
컴포넌트는 `--color-*` 시맨틱 토큰만 쓴다. `--palette-*`는 `tokens.css` 안에서만 참조한다. (SEED 규칙과 동일)

**팔레트**
- 회색: SEED gray 스케일 그대로 (`00 #fff` … `1000 #1a1c20`)
- 브랜드 **아이(藍)**: 츠기 고유 남색 스케일. SEED의 carrot 자리에 들어간다. (`600 #2d4b8e` 기준)
- 대표 아이콘 전용 **주홍(朱)** `500 #ff5a3c`·**감(紺)** `900 #16204a`: 아이콘 파일에만 쓴다. 화면의 버튼·칩·링크는 계속 아이다 — 주홍은 상태 색(carrot·red)과 헷갈려서 시맨틱 토큰으로 만들지 않는다.
- 상태 색: SEED green·carrot·yellow·red·blue

**시맨틱 역할** (SEED 명명 규칙 `bg/fg/stroke` + 역할 + 강도)

| 토큰 | 용도 |
|---|---|
| `--color-bg-layer-default` | 화면 바탕(흰색) |
| `--color-bg-layer-basement` | 섹션 구분 띠, 이미지 자리 |
| `--color-bg-layer-floating` | 앱 바·하단 바·스낵바 아래 |
| `--color-bg-neutral-weak` / `-pressed` | 회색 버튼·칩·콜아웃 |
| `--color-bg-neutral-solid` | 선택된 칩, 스낵바 |
| `--color-bg-brand-solid` / `-pressed` | 주요 버튼(화면당 1개) |
| `--color-bg-brand-weak` | 브랜드 강조 배경 |
| `--color-bg-transparent-pressed` | 리스트 아이템 눌림 |
| `--color-bg-overlay` | 바텀 시트 뒤 어둡게 |
| `--color-fg-neutral` | 본문·제목 |
| `--color-fg-neutral-muted` | 보조 본문 |
| `--color-fg-neutral-subtle` | 메타 정보(동네·기간) |
| `--color-fg-placeholder` / `-disabled` | 자리표시·비활성 |
| `--color-fg-brand` | 링크, 선택 탭 |
| `--color-fg-on-brand-solid` | 브랜드 버튼 위 글자 |
| `--color-stroke-neutral-muted` | 리스트 구분선 |
| `--color-stroke-neutral-weak` | 입력·외곽선 |
| `--color-stroke-focus-ring` | 포커스 링 |

**츠기 전용: 소식 유형(노선색)**
기존 "역 노선색" 메타포를 SEED 톤 체계에 얹는다. 유형마다 `fg`(글자·점)와 `bg-weak`(배지 바탕) 한 쌍을 둔다.

| 유형 | 라벨 | SEED 톤 | 토큰 |
|---|---|---|---|
| `new` | 새로 오픈 | positive (green) | `--color-type-new-fg` / `-bg` |
| `limited` | 기간 한정 | carrot (주홍) | `--color-type-limited-fg` / `-bg` |
| `changed` | 최근 변화 | warning (yellow) | `--color-type-changed-fg` / `-bg` |
| `editorial` | 편집 추천 | brand (아이) | `--color-type-editorial-fg` / `-bg` |

- 유형 색은 **배지·썸네일 자리표시·상세 기간 블록**에만 쓴다. 버튼·링크에 쓰지 않는다.
- "재확인 필요"는 warning 톤 배지, "종료됨"은 neutral 톤 배지 + 흐림(opacity .4 금지 → `fg-disabled`).
- **다크 모드 (웹만)**: 기본은 기기 설정을 따른다. 설정 화면에서 **시스템 설정 따르기 / 라이트 / 다크** 셋 중에 고를 수 있다. 앱인토스는 라이트로 고정하고 설정 버튼을 숨긴다.
  - 참고한 패턴: 토스(전체 → 설정 → 화면 설정), 카카오톡(더보기 → 설정 → 테마) 모두 기본값은 기기 설정이고, 설정 안에서 세 가지 중 하나를 고른다.
  - `lib/channel.ts`의 `applyColorMode(pref)`가 설정과 기기 설정을 합쳐 `<html data-theme="dark">`을 달거나 뗀다. 기기 설정이 바뀌면 바로 따라간다.
  - 설정 값은 `lib/storage.ts`의 `tsugi:theme`(기본값 `system`이면 저장하지 않음).
  - 다크 값은 `tokens.css`의 `[data-theme='dark']` 블록에서 **시맨틱 토큰만** 덮어쓴다. 컴포넌트는 손대지 않는다.
  - 값은 SEED 다크 테마 기준: 바탕 `#16171b`, 앱 바·탭 바 `#1d2025`, 섹션 띠 `#000`. 유형 색은 밝은 글자 + 어두운 바탕 쌍으로 바꾼다. 브랜드 글자는 밝은 남색 `#94a9e2`.
  - 새 시맨틱 토큰을 만들면 다크 값도 같이 정한다. 빠뜨리면 다크에서 라이트 값이 그대로 보인다.

### 1.2 타이포그래피
글꼴: Pretendard Variable → 시스템 고딕. 일본어 표기는 `.ja`(Noto Sans JP 우선).
스케일은 SEED `t1~t10`을 그대로 쓴다.

| 토큰 | 크기/행간 | 츠기 용도 |
|---|---|---|
| `t2` | 12/16 | 배지 |
| `t3` | 13/18 | 메타(동네·확인일·일본어 이름) |
| `t4` | 14/19 | 칩, 보조 본문, 버튼(소) |
| `t5` | 16/22 | 본문, 리스트 제목, 버튼(대) |
| `t6` | 18/24 | 섹션 제목, 앱 바 제목 |
| `t7` | 20/27 | — |
| `t8` | 22/30 | 상세 장소 이름 |
| `t9` | 24/32 | 브랜드 워드마크 |

굵기는 400·500·700 세 가지만. 제목 700, 칩·탭 500, 본문 400.

### 1.3 간격·레이아웃
- 4px 그리드. SEED `x1(4)…x16(64)` 토큰.
- **글로벌 거터 16px** (`--space-gutter`). 모든 화면 좌우 여백.
- 리스트 아이템 세로 패딩 16px, 섹션 사이 8px 회색 띠(`bg-layer-basement`)로 끊는다.
- 콘텐츠 최대 폭 560px, 가운데 정렬.
- 고정 영역: 상단 앱 바 56px, 하단 탭 바 56px(+safe-area), 상세 하단 액션 바 64px(+safe-area).

### 1.4 모서리·그림자·모션
- 모서리: 배지 `r1(4)`·`r1_5(6)`, 썸네일 `r2(8)`, 버튼(중) `r2(8)`, 버튼(대) `r3(12)`, 콜아웃 `r2_5(10)`, 칩 `full`.
- 그림자: 떠 있는 것(스낵바)만 `s2`. 카드에 그림자·테두리를 두르지 않는다 — 리스트는 구분선으로 나눈다.
- 모션: 색 전환 150ms `easing`, 누름 축소 `scale(.97)` 150ms, 스낵바 등장 200ms `enter`. `prefers-reduced-motion`이면 끈다.

### 1.5 아이콘
- 라이브러리를 쓰지 않는다. `components/Icon.tsx`의 인라인 SVG(24 그리드, 1.8px 선, `currentColor`).
- 탭 바·앱 바·저장(하트) 같은 반복 행동에만 쓴다. 아이콘만 있는 버튼은 반드시 `aria-label`.

### 1.5.1 대표 아이콘 (앱 아이콘·파비콘·홈 화면)
- 확정안: **"つ 한 획"** (2026-11-10 사용자 결정, 같은 날 정한 "아이 노선"을 대체 — 탁한 남색 바탕과 십자(+)가 구식·의료 기호처럼 읽혔다). 주홍 바탕에 「つぎ」의 つ를 흰 노선 한 획으로 그리고, 끝에 다음 정차(흰 원 안 감색 점)를 찍는다. 글자·배경선·장식을 더하지 않는다. 공유 미리보기(`og:image`) 기본 이미지도 이 아이콘(`icon-1024.png`)이다 — 글자 든 가로형 og.png는 2026-11-10 사용자 요청으로 없앴다.
- 그림은 가운데 80% 원(반지름 410) 안에 둔다. 안드로이드 maskable 아이콘(`icon-512.png`)이 원·스쿼클로 잘려도 획이 잘리지 않는다.
- 원본은 `app/public/icon.svg`(1024 정사각, 모서리 깎지 않음). PNG(`favicon-32`·`apple-touch-icon`(180)·`icon-192`·`icon-512`·`icon-1024`)는 `scripts/icon/icon.html` 주석의 명령으로 다시 만든다(헤드리스 Chrome으로 그 파일을 크기별로 찍는다). 앱인토스 콘솔 업로드는 `icon-1024.png`에서 필요한 크기로 만든다.
- `index.html`과 공유 페이지(`build-share.mjs`)가 같은 아이콘·`manifest.webmanifest`를 건다. manifest의 `display`는 `browser` — 홈 화면에서 따로 열리면 사파리 저장 목록과 저장소가 갈라지기 때문이다.
- 아이콘 파일은 CSS 변수가 닿지 않아 색 코드를 직접 쓴다(`tokens.css`의 주홍 500 `#ff5a3c`·감 900 `#16204a`·흰색만). `manifest.webmanifest`의 `theme_color`도 주홍 500이다. 색을 바꾸면 tokens.css·manifest와 함께 고친다.
- 발견 화면 앱 바의 대표 아이콘 28(웹만)은 같은 `icon.svg`를 쓴다. 워드마크 글자는 본문 색 그대로 두고, 화면 안에서 주홍은 이 아이콘 한 곳에만 나온다.

### 1.6 접근성 (SEED Inclusive Design)
- 누를 수 있는 곳 최소 44×44px.
- 본문 대비 4.5:1 이상 (`fg-neutral-subtle #555d6d`까지는 흰 바탕에서 통과).
- 색만으로 뜻을 전하지 않는다: 유형 배지에는 항상 글자 라벨, 상태 변화는 `role="status"` 스낵바로도 알린다.
- `:focus-visible`에 2px 포커스 링.

### 2.1 장소 리스트 아이템 (가장 중요한 컴포넌트)

```
┌──────┐  [● 기간 한정 D-12]  시부야
│ 썸네일 │  카페 레가토  カフェ・レガート
│ 88px │  왜 갈까 한 줄이 두 줄까지 보입니다…
└──────┘  12.31까지                         ♡
```
- 1행: 유형 배지(+D-day/예정) · 동네
- 2행: 한국어 이름(t5 700), 그 아래 일본어 이름(t3 subtle, 한 줄 말줄임)
- 3행: `why` 두 줄 말줄임 (t4 muted)
- 4행: 언제(기간) / 오른쪽 하트 저장. 확인일은 목록에 두지 않고 상세 「무엇을 확인했을까」에서만 보인다(재확인이 필요하면 1행 배지로 알린다)
- 짝 장소(`pairWith`)가 있으면 3행 아래 "근처 한 곳 · 이름" t3 brand
- 행 전체가 상세 링크, 하트만 별도 버튼(링크 밖에 둔다)

### 2.2 장소 상세 (6블록)
순서는 기획안 그대로: 왜 갈까 → 누구에게 맞을까 → 언제 갈 수 있을까 → 무엇이 다를까 → 어떻게 끼워 넣을까 → 무엇을 확인했을까.
- 상단: 4:3 이미지 프레임 → 배지 줄 → 이름(t8) → 일본어 이름·주소(t3).
- 블록마다 제목 t4 700 subtle(라벨처럼) + 본문 t5. 블록 사이 구분선.
- "언제" 블록은 소식마다 유형 배지 + 날짜 + D-day 한 줄.
- 빈 블록은 숨기지 않고 "확인 중"을 placeholder 색으로.
- 하단 액션 바: 왼쪽 하트(저장) | 오른쪽 **지도 열기**(brand-solid lg). 공유는 앱 바 오른쪽.


### 2.3 날짜 달력 (DateSheet)
브라우저 기본 날짜 입력은 기기 언어에 따라 `mm/dd/yyyy`로 보여서 직접 그린다 (`components/DateSheet.tsx`, 라이브러리 없음).
- Date Field를 누르면 Bottom Sheet로 한 달 달력이 올라온다. 오늘 이전은 비활성.
- **여행 날짜(range)**: 출발·귀국 어느 칸을 눌러도 같은 시트. 위에 「출발 → 귀국」 요약 두 칸(다음에 고를 칸에 브랜드 테두리), 달력에서 출발→귀국 순서로 누른다. 사이 날짜는 `bg-brand-weak` 띠로 잇고, 양 끝은 `bg-brand-solid` 원. 아래에 「N박 N+1일」과 「다시 고르기」(neutral-weak) · 「이 날짜로 정하기」(brand-solid, 둘 다 골라야 활성).
- **방문 예정일(single)**: 날짜를 누르면 바로 정하고 닫힌다. 값이 있으면 「날짜 지우기」.
- 날짜 칸 44×44 원형, 숫자 t5 tabular-nums. 오늘은 숫자 아래 브랜드 점. 요일 머리 t3 subtle(일요일 시작).
- 월 이동은 앱 바처럼 좌우 아이콘 버튼. 이번 달보다 앞으로는 가지 않는다.
- Esc·바깥 누르기·닫기 버튼으로 닫힌다. 열리면 시트에 포커스, 닫히면 원래 칸으로 돌아간다.

## 3. 화면 패턴

| 화면 | 앱 바 | 구성 |
|---|---|---|
| 발견 `#/` | 대표 아이콘 28(r2, 웹만) + 워드마크 "츠기"(t9 700, `fg-neutral`) + 부제, 오른쪽 설정 버튼(웹만) | 칩 줄(도시 → 동네 → 취향, 가로 스크롤). 도시 줄은 장소가 있는 도시가 2곳 이상일 때만, 동네 줄은 도시가 정해졌을 때만(그 도시의 동네, 첫 칩 「○○ 전체」). 장소가 없는 도시·동네 칩은 만들지 않는다. URL `?city=&hood=` → 여행 날짜 필드 → 새 소식 / 편집 추천 리스트 |
| 상세 `#/p/:id` | ← 뒤로 · 공유 | 위 2.2 |
| 지도 `#/map` | "지도" + 오른쪽 「목록으로 보기」(neutral-weak sm) | 하트 아이콘 칩(저장한 곳, `?saved=1`, `aria-label`, 줄 맨 앞 + 구분선) → 도시 칩 줄(「전체」=`?city=all`) → 도시를 고르면 동네 칩 줄 → 지도(MapLibre + OpenFreeMap Positron, 지명은 한국어 우선, 탭 바 위까지 꽉 채움) → 마커 누르면 Map Preview Card. `?view=list`면 동네별 목록(여러 도시면 제목이 「오사카 · 우메다」), `?city=`·`?hood=`로 필터. 필터 없이 들어오면(`#/map`) 첫 도시(labels.json 순서, 도쿄)를 고른 상태로, 그 도시 첫 동네의 첫 장소를 가운데에 둔다(줌 15). 다크 모드에서는 OpenFreeMap Dark 스타일로 바뀐다. 회전·기울이기는 끈다 |
| 설정 `#/settings` | ← 뒤로 · "설정" | 탭 바 숨김. "화면 테마" 리스트 헤더 → Radio List(시스템·라이트·다크, 웹만) → "이용 통계"(보내기·보내지 않기, 통계를 보내는 채널만) → "약관·정책"(개인정보 처리방침으로 이동). 고르는 즉시 적용 |
| 처리방침 `#/privacy` | ← 뒤로 · "개인정보 처리방침" | 탭 바 숨김. Prose 한 덩어리, 맨 아래 시행일 |
| 저장 `#/saved` | "저장" | 보관 링크 콜아웃(+버튼) → 동네별 리스트(여러 도시를 저장했으면 제목에 도시) → 아이템(방문 예정일 필드·지도 열기) |

**빈 상태**: 가운데 정렬, 아이콘 48(subtle) + 한 줄 설명(t5) + 행동 버튼 하나.
**불러오기 실패 없음**: 콘텐츠는 번들에 있으므로 로딩 스피너를 두지 않는다.

## 4. 문구 (SEED Writing 규칙 + 츠기 편집 규칙)

- **해요체**가 기본. "저장했어요", "링크를 복사했어요". 경고성 안내만 합니다체 허용.
- 존댓말 과잉 금지: "하실 수 있어요" ✗ → "할 수 있어요" ✓
- 버튼·탭·제목에는 마침표를 찍지 않는다. 문장 안내에는 찍는다.
- 버튼은 **행동 + 대상**: "지도 열기", "링크로 보관하기", "저장에 더하기". "확인", "OK" 단독 금지.
- 기능 이름보다 사용자 목적: "공유했어요" ✓ / "공유 완료" ✗
- 숫자는 아라비아 숫자. 소식 날짜는 `M.D`(`lib/dates.ts`의 `formatDate`), 확인일은 `YYYY.MM.DD`, D-day는 `D-12`, 당일은 `D-DAY`.
- 줄임말·은어 금지. take의 `why`에 "핫한·인생·현지인만" 금지 (validate가 검사).
- 부정보다 긍정: "이 조건엔 아직 후보가 없어요. 동네를 하나 더 넣어 볼까요?"
- 오류는 해결 방법을 말한다: "링크를 복사하지 못했어요. 아래 주소를 길게 눌러 복사해 주세요."

### 4.1 콘텐츠 말투 (장소 상세·목록에 나오는 편집 글)
한 화면에 이어 읽히므로 문장은 해요체로 맞춘다. 마침표는 찍지 않는다(화면 안내 문구와 달리 콘텐츠 블록은 한 덩어리 글로 본다). 2026-11-10 사용자 결정.

| 필드 | 화면 | 말투 | 예 |
|---|---|---|---|
| take `why` | 왜 갈까, 목록 한 줄 | 해요체, 80자 이내 | "…아침 9시부터 자정까지 열어요" |
| take `forWhom` | 누구에게 맞을까 | 명사로 끝냄(「~ 사람」) — 물음의 답 | "…커피 한 잔이 필요한 사람" |
| take `notFor` | 기대와 다를 수 있는 사람 | 해요체 | "…흡연석이에요 (안은 금연 48석)" |
| take `differsFrom` | 무엇이 다를까 | 해요체 | "…후쿠오카 토박이 가게예요" |
| update `note` | 기간 옆 메모 | 메모체(명사·조건 나열) | "현금만", "부정기 휴무" |

- 끝의 괄호 보충(`(예약 불가)`)은 괜찮다. 괄호 앞 문장이 해요체면 된다.
- `scripts/validate.mjs`가 `why`·`notFor`·`differsFrom`의 끝(~요, 마침표 없음)을 검사한다.
- 같은 블록의 화면 문구(「상시 방문할 수 있어요」)도 마침표 없이 쓴다.

## 5. 구현 규칙

- 색·글꼴·간격·모서리·그림자·모션 값은 **`tokens.css`에만** 쓴다. `global.css`와 컴포넌트는 `var(--…)`만.
- 컴포넌트 `style={{}}`에 색·간격 숫자를 쓰지 않는다. 유형 색 주입(`--type-fg`, `--type-bg`)만 예외.
- 새 화면을 만들 때 위 컴포넌트 표에 없는 모양이 필요하면 먼저 이 문서에 추가한다.
- 토스(앱인토스) 채널도 같은 화면을 쓴다. 토스 WebView는 자체 상단 바를 주므로 `CHANNEL === 'toss'`일 때도 앱 바는 그대로 두되, 분기가 필요하면 `lib/channel.ts`에서만 한다.
